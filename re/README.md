# `re/` — reverse-engineering archive

The primary-source corpus: 32-bit disassembly dumps, string extractions and
derived analysis notes behind every `Facts.py` decode. Keep it: the pending
write-driver work re-verifies erase/program packet shapes **against these
dumps** (see `msi_isp/cli.py` write stub), and the project's anti-confabulation
discipline (session 15h) means claims should stay checkable against bytes.

## Tools (all via `. re/env.sh` first — sets `$PY`, capstone/pefile, DLL paths)

| file | purpose |
|---|---|
| `pexray.py` | shared PE/capstone helper (32-bit mode — see bitness note) |
| `dis32.py`, `d2.py`, `d32 helpers` | 32-bit x86 disasm plumbing |
| `dump.py`, `dumpfn.py`, `dumpd.py`, `pdump.py` | function/export dumpers |
| `strs.py`, `fsum.py`, `steps.py` | string extraction, immediate summaries, decision-surface skeletons (how the ISP pipeline was decoded — session 14f) |

## Dump-file prefixes (verified against file headers, audit 15l)

| prefix | content |
|---|---|
| `exp_comm`, `exp_commaux` | export tables (name -> RVA) for Comm.dll / Comm_Aux.dll |
| `a_*`, `b_*`, `o_*` | Comm_Aux.dll function dumps (32-bit passes; `b_initdev`/`b_stub`/`a_sub*` = tunnel/thunks; `o_initial` = InitialDev; `o_gfxi2c_ids` = rtd38 GFXI2C) |
| `c_*` | Comm.dll functions by RVA (`c_rf` = ReadFlashData 0x7e50, `c_ie`, `c_3c80`, ...) |
| `f_*` | Comm.dll named functions (`f_readflash`, `f_autoenter`, `f_enter`, `f_aux_txn` era naming) **and** `P!P:` WinIspPlugIn dumps (`f_ispattempt`, `f_getflash_type`, `f_douispraw`, `f_ispflash_full`, `f_ispsteps` = the flash-pipeline narration) |
| `g_*` | WinIspPlugIn/engine dumps (`g_dump_int` = the DumpFlash worker, `g_3c80`, `g_sw3c80`...) **plus two curated analysis outputs**: `g_ispopseq.txt` (register-sequence extraction feeding `Facts.ISP_PIPELINE`) and `g_flashdat_map.txt` (generated by `scratch/flashdat_bind.py` — do not hand-edit) |
| `x_*` | second-pass dumps of the flash-read/write chain (`x_readflash`, `x_ispflash`) |
| `w_*`, `wreg/wrex/w32bre/rreg` | register-file primitives — WriteReg/WriteRegEx/Write32BitRegEx/ReadReg/DDCCIRead: the exact shapes `msi_isp/isp.py` emulates |
| `wire1..9` | DDC/CI read/write function-chain dumps (wire layer) |
| `u_*` | RealtekUSB backend functions (USB path — relevant to the GI/CpIspTool lineage, `Facts.GI_BUNDLE`) |
| `str_comm`, `str_isp`, `keys_aux` | string/data extractions from the DLLs |
| `plg1` | plugin `GetFWInfo` dump |

## Bitness warning — RESOLVED (audit 15l)

HANDOFF warned that files predating commit `b367ef6` might carry 64-bit-mode
garbage (`push rbp` for opcode `55`, rip-relative operands, `movabs`, stray
`hlt`). A full-corpus scan found exactly five such dumps plus four crash-
traceback captures; all nine were **deleted** in 15l (uncited, zero evidentiary
content, retrievable via `git show <old-hash>:<path>`). Surviving dumps are
clean 32-bit or non-disassembly artifacts. If you regenerate any dump, compare
the prologue: `55` must decode as `push ebp`.
